# SP2b Implementation Plan — optional DAQ commands, the timestamp field, and PID_OFF

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the five remaining optional DAQ commands, the per-list timestamp field, and `PID_OFF`, so a master can discover DAQ lists and event channels, read back its own configuration, synchronise its clock, and receive timestamped measurement data.

**Architecture:** Five new handlers on a dispatch table that already works, plus one new field in a DTO the sampler already builds. The clock comes from a new integrator callback, because the module holds no clock. `WRITE_DAQ` and `WRITE_DAQ_MULTIPLE` share one entry-application helper so the specification's "same restrictions" clause holds by construction. Nothing in the transmission chain, the DTO ring, or the exclusive area changes.

**Tech Stack:** C (AUTOSAR-style BSW), Jinja2 code generation via `bsw_code_gen` 0.1.14, CMake, pytest + CFFI compiling the real C inside an Alpine Docker image.

**Spec:** `docs/superpowers/specs/2026-09-02-xcp-daq-sp2b-design.md`

## Global Constraints

- Citations in new code are to **XCP Part 2 - Protocol Layer Specification 1.1**. Existing comments keep their 1.0 citations (SP2a DD1). §1.6.4 is renumbered wholesale between versions — never copy a §1.6.4 citation from 1.0 code into new code.
- The 1.1 PDF is a scan and its OCR is unreliable for `TIMESTAMP_MODE` and `WRITE_DAQ_MULTIPLE`. Bit layouts in this plan were read from the 1.0 PDF (text) and cross-checked. Where a value is 1.1-only it is flagged; confirm it against the PDF page images before relying on it.
- `Xcp_DaqListRt(n)` is an **unchecked** accessor. Every call site must first gate on `Xcp_DaqListIsValid(n)`.
- Every `SchM_Enter_Xcp_DtoQueue` needs a matching `SchM_Exit_Xcp_DtoQueue` on every path. The `_callback_invariants` autouse fixture in `test/conftest.py` fails any test that leaks or double-takes the area.
- An exception raised inside a CFFI callback is recorded by `_callback_invariants` and fails the test. Assertions inside mocks are live — use them.
- Run the suite with `docker run --rm --user $(id -u):$(id -g) -v $(pwd):/usr/project xcp-test:local sh -c "cd /usr/project && ./test.sh"`. It takes ~3m30s and runs everything; `test.sh` accepts no arguments.
- For a focused run, configure with `-DXCP_PYTEST_ARGS='-k;<expr>'`. **It is a CMake cache variable** — clear it with `-DXCP_PYTEST_ARGS=` before the next full run, or that run silently executes only the filtered subset.
- `MAX_ODT_ENTRY_SIZE_DAQ` as reported by `GET_DAQ_RESOLUTION_INFO` never changes: it stays `MAX_DTO - identification field size`. The timestamp reduces the *budget of ODT 0*, not the reported value.
- `Xcp_TimestampTypeType`'s enumerators are implicit: `NO_TIME_STAMP == 0`, `ONE_BYTE == 1`, `TWO_BYTE == 2`, `FOUR_BYTE == 3`. The wire encoding of the `TIMESTAMP_MODE` size field is 0, 1, 2, **4** — 3 is "Not allowed". Never write the enumerator into the size bits.
- Commit messages use the repository's convention: `feat:`, `fix:`, `test:`, `docs:`, `refactor:`, `chore:`.

## Task Order and Why

**1–2** build the configuration and the callback everything else consumes.

**3–6** are the timestamp, split so a reviewer can reject one half without the other: 3 reports it, 4 lets the master switch it on, 5 covers the opposite configuration order, 6 actually transmits it. Task 5 exists separately from 4 because the two enforce the same rule at opposite ends of the master's choice of sequence, and a reviewer should be able to judge each on its own.

**7 and 8** are independent of each other and of the timestamp work, except that 7 edits a function 6 also edits — run them in order.

**9** is a pure refactor with no behaviour change, which is exactly why it is its own task: it must be reviewable as "every test still passes and no test changed". **10 depends on it.**

**11–13** are independent handlers. **14** extends the acceptance sweep once every feature exists, because a dimension added earlier would have to be re-swept. **15** documents.

- [ ] **Step 5: Fill TIMESTAMP_MODE and TIMESTAMP_TICKS in `Xcp_DTOCmdDaqGetDaqResolutionInfo`**

Replace the two placeholder writes and their SP2a comment. Add a file-local helper above the handler:

```c
/**
 * @brief Maps Xcp_TimestampTypeType onto the TIMESTAMP_MODE size field.
 *
 * @details XCP part 2 - Protocol Layer Specification 1.1/1.6.4.1.2.5 encodes the size in bits 2:0
 * as 0, 1, 2 or 4, and marks 3 "Not allowed". Xcp_TimestampTypeType's enumerators are implicit, so
 * FOUR_BYTE is 3 -- passing the enumerator through unmapped would transmit precisely the value the
 * specification forbids.
 */
static uint8 Xcp_TimestampWireSize(Xcp_TimestampTypeType type)
{
    uint8 size;

    switch (type)
    {
        case ONE_BYTE:
            size = 0x01u;
            break;
        case TWO_BYTE:
            size = 0x02u;
            break;
        case FOUR_BYTE:
            size = 0x04u;
            break;
        case NO_TIME_STAMP:
        default:
            size = 0x00u;
            break;
    }

    return size;
}
```

Then in the handler:

```c

     * TIMESTAMP_MODE: bits 2:0 size, bit 3 TIMESTAMP_FIXED, bits 7:4 unit. TIMESTAMP_FIXED stays
     * clear because the master switches the timestamp per DAQ list through SET_DAQ_LIST_MODE. */
    Xcp_Internal.cto_response.pdu_info.SduDataPtr[0x05u] =
            (uint8)(Xcp_TimestampWireSize(Xcp_Ptr->general->timestampType) |
                    (uint8)((uint8)Xcp_Ptr->general->timestampUnit << 0x04u));
    Xcp_CopyFromU16WithOrder(Xcp_Ptr->general->timestampTicks,
```

```c
uint8 Xcp_DTOCmdDaqWriteDaqMultiple(boolean *responseExpected, const PduInfoType *pPduInfo)
{
    const uint8 count = pPduInfo->SduDataPtr[0x01u];
    uint8 error = 0x00u;
    uint8_least idx;

    *responseExpected = TRUE;

    /* 1.1/1.6.4.1.2.1: each element is BIT_OFFSET, size, address DWORD, address extension and a
     * mandatory alignment dummy -- 8 bytes, including after the last element. */
    if ((PduLengthType)pPduInfo->SduLength < (PduLengthType)(0x02u + ((PduLengthType)count * 0x08u)))
    {
        error = XCP_E_ASAM_CMD_SYNTAX;
    }
    else
    {
        for (idx = 0x00u; (idx < (uint8_least)count) && (error == 0x00u); idx++)
        {
            const uint8 *p_element = &pPduInfo->SduDataPtr[0x02u + (idx * 0x08u)];
            uint32 address;

            Xcp_CopyToU32WithOrder(&p_element[0x02u], &address, Xcp_Ptr->general->byteOrder);

            /* Applied as the loop walks them: 1.6.4.1.2.1 says "it is not possible to detect which
             * entry caused the error. In that case the whole configuration is invalid", so the
             * master must reconfigure regardless and a rollback would buy nothing. */
            error = Xcp_DaqApplyOdtEntry(p_element[0x00u], p_element[0x01u], p_element[0x06u], address);
        }
    }

    if (error == 0x00u)
    {
        Xcp_Internal.cto_response.pdu_info.SduDataPtr[0x00u] = XCP_PID_RESPONSE;
        Xcp_FinalizeResPacket(0x01u, &Xcp_Internal.cto_response.pdu_info);
    }
    else
    {
        Xcp_FillErrorPacket(error, &Xcp_Internal.cto_response.pdu_info);
    }

    return E_OK;
}
```

```c
{
    uint16 daq_list_number;
    uint8 properties = 0x00u;

    *responseExpected = TRUE;

    Xcp_CopyToU16WithOrder(&pPduInfo->SduDataPtr[0x02u], &daq_list_number, Xcp_Ptr->general->byteOrder);

    if (Xcp_DaqListIsValid(daq_list_number) != TRUE)

         * returned.' */

         * not the configured triggeredDaqListRef -- so the master may move a list between

        Xcp_Internal.cto_response.pdu_info.SduDataPtr[0x01u] = properties;

        Xcp_FinalizeResPacket(0x06u, &Xcp_Internal.cto_response.pdu_info);
```
