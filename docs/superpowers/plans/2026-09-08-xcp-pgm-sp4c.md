# SP4c Implementation Plan — sectors, formats and verification

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Complete SP4 and the PGM command group by adding `GET_SECTOR_INFO` (0xCD), `PROGRAM_FORMAT` (0xCB) with functional access mode and the Block Sequence Counter, and `PROGRAM_VERIFY` (0xC8).

**Architecture:** Six tasks, ordered so each is independently testable. The thin, self-contained commands come first and establish SP4c's plumbing pattern; the sector configuration model follows; then the format state, the Block Sequence Counter it initialises, and the two functional-mode paths, which are independent of each other because the specification makes clearing's access mode independent of programming's.

**Tech Stack:** C (AUTOSAR-style, MISRA-leaning), Python 3.7 + pytest + CFFI, CMake, Jinja2 code generation, Docker.

**Spec:** `docs/superpowers/specs/2026-09-08-xcp-pgm-sp4c-design.md` (DD84–DD93)

## Global Constraints

- **`./test.sh` is the only authoritative run, and it MUST run in Docker.** On the host it dies at `cmake: not found`, and piping it reports the pipe's exit code — a failure can read as success. Use exactly:
  ```
  docker run --rm --user "$(id -u):$(id -g)" --env HOME=/tmp --ulimit nofile=65536:524288 --volume "$PWD:/usr/project" --workdir /usr/project xcp-test:sp4b ./test.sh
  ```
  `--user` is load-bearing: a root run leaves root-owned files under `build/` that later runs cannot delete, surfacing as a failing `Xcp_GateOnCompiles` with **no compile error in it**. Fix by deleting `build/` from a root container, not by debugging code.
- **Subset runs:** seed the CMake *cache* first, then run `./test.sh`:
  ```
  docker run --rm --user "$(id -u):$(id -g)" --env HOME=/tmp --volume "$PWD:/usr/project" --workdir /usr/project/build xcp-test:sp4b cmake .. -DXCP_ENABLE_TEST=ON -DXCP_PYTEST_ARGS="-k;pgm"
  ```
  **Clear it (`-DXCP_PYTEST_ARGS=""`) and run the full suite before finishing any task.** A full clean run is ~6.5 minutes. Baseline at branch point: **12902 passed, 29 skipped**, both ctest targets.
- **NEVER `rm -rf generated/*`** — it holds a tracked `generated/CMakeLists.txt`.
- **`Xcp_Internal` and file-`static` tables are NOT reachable from the CFFI harness.** `test/conftest.py` builds its cdef from `interface/Xcp.h` alone. Every assertion observes transmitted bytes. "Does not inspect internal state" is not a valid review finding.
- **Mutation verification is required per task**, and **per term** for compound conditions rather than per outcome.
- **If a pre-existing test outside your task's files fails, stop and report — do not adjust it.** Three tasks on the predecessor branch hit exactly this, and each needed a ruling.

**Protocol values, verified against the 1.0 PDF and the 1.1 OCR:**

| Thing | Value |
|---|---|
| `GET_SECTOR_INFO` request | `(0xCD, mode, sector_number)`; mode 0 = start address, 1 = length |
| `GET_SECTOR_INFO` response | `(0xFF, clear_seq, program_seq, programming_method, DWORD sector_info)` |
| `PROGRAM_FORMAT` request | `(0xCB, compression, encryption, programming_method, access_method)` |
| `PROGRAM_VERIFY` request | `(0xC8, verification_mode, WORD verification_type, DWORD verification_value)` |
| `PROGRAM_CLEAR` request | `(0xD1, mode, WORD reserved, DWORD clear_range)` — mode 0 absolute, 1 functional |
| Functional clear range bits | `0x01` calibration areas, `0x02` code areas, `0x04` NVRAM, `0x08…0x80` **reserved**, `0x0100…0xFFFFFF00` user defined |
| Verification type bits | `0x0001` calibration, `0x0002` code, `0x0004` complete flash, `0x0008…0x0080` **reserved**, `0x0100…0xFF00` user defined |
| Access method | `0x00` absolute (default), `0x01` functional, `0x80…0xFF` user defined |
| Error codes | `ERR_OUT_OF_RANGE` 0x22, `ERR_MODE_NOT_VALID` 0x27, `ERR_SEGMENT_NOT_VALID` 0x28, `ERR_SEQUENCE` 0x29, `ERR_VERIFY` 0x32 |
| `PGM_PROPERTIES` bits | `ABSOLUTE_MODE` 0, `FUNCTIONAL_MODE` 1, `COMPRESSION_SUPPORTED` 2, `COMPRESSION_REQUIRED` 3, `ENCRYPTION_SUPPORTED` 4, `ENCRYPTION_REQUIRED` 5, `NON_SEQ_PGM_SUPPORTED` 6, `NON_SEQ_PGM_REQUIRED` 7 — already defined in `source/Xcp_Internal.h` |

All five error values were read from the specification's own error-code table (§1.7.3.1, *Table of Error Codes (ERR_*)* — verified, listing `ERR_OUT_OF_RANGE 0x22`, `ERR_MODE_NOT_VALID 0x27`, `ERR_SEGMENT_NOT_VALID 0x28`, `ERR_SEQUENCE 0x29`, `ERR_VERIFY 0x32`) and cross-checked against `interface/Xcp_Errors.h`, which is where this module's `XCP_E_ASAM_*` constants live — use those constants in C rather than literals.

**Precedents to mirror rather than invent:**
- Config array model: `Xcp_SegmentType` / `maxSegment` / `const Xcp_SegmentType *segment` in `interface/Xcp_Types.h` (ends line 565) and its generation in `script/source_cfg.c.jinja2`.
- API enable flags: `xcp_program_clear_api_enable` at `config/xcp.schema.json:321`, in the same object and in its `required` list near `:422`.
- Deferred/polled callbacks: `Xcp_PgmPollPendingCommand` and `Xcp_PgmCompletePendingCommand` in `source/Xcp_Pgm.c`.
- PGM tests: `test/pgm_clear_test.py` for handle construction, `test/pgm_acceptance_test.py` for end-to-end pumping.

### Task 2: the sector model and `GET_SECTOR_INFO` (0xCD)

**Files:**
- Modify: `config/xcp.schema.json`, `interface/Xcp_Types.h`, `script/source_cfg.c.jinja2`, `source/Xcp_Pgm.c`, `source/Xcp.c`
- Test: `test/pgm_sector_test.py` (create)

**Interfaces:**
- Consumes: Task 1's plumbing pattern.
- Produces: `Xcp_SectorType { const uint32 address; const uint32 length; const uint8 clearSequenceNumber; const uint8 programSequenceNumber; const uint8 programmingMethod; }`, plus `maxSector` and `const Xcp_SectorType *sector` on the config type. Task 6's end-to-end run uses sectors.

- [ ] **Step 1: Write the failing tests**

Create `test/pgm_sector_test.py`:

1. Mode 0 returns the configured start address in bytes 4–7, with the two sequence numbers and programming method in bytes 1–3, for a multi-sector configuration where **all five values differ per sector** — so a handler returning the wrong sector's data fails.
2. Mode 1 returns the length. **Configure `address_granularity` WORD or DWORD for this test** (DD87): 1.0 reads the field as AG units and 1.1 as bytes, and at AG = BYTE the two are indistinguishable, so a BYTE-only test proves nothing.
3. A sector number equal to `MAX_SECTOR` is refused `(0xFE, 0x28)` `ERR_SEGMENT_NOT_VALID` — **not** `ERR_OUT_OF_RANGE`, per DD88.
4. A mode byte other than 0 or 1 is refused `(0xFE, 0x27)` `ERR_MODE_NOT_VALID`.
5. **The cross-command invariant:** `GET_PGM_PROCESSOR_INFO`'s `MAX_SECTOR` byte equals the configured sector count, asserted in the same test as a `GET_SECTOR_INFO` walk over `0…MAX_SECTOR-1` that succeeds for every index and fails at `MAX_SECTOR`. Both halves in one test, so drift in either is caught.
6. Sequence numbers are reported verbatim, using the specification's own example: sectors whose clear order is 0,1,2 while their program order is 5,4,3.

Seed `-DXCP_PYTEST_ARGS="-k;pgm_sector"`. Record each failure.

Generation: emit the array in `script/source_cfg.c.jinja2` following the segment precedent.
