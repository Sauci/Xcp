# SP3 — Synchronous Data Stimulation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let an XCP master write ECU memory synchronously — send stimulation data that the slave buffers and applies at an event trigger.

**Architecture:** Reception decodes a STIM DTO's identification field, copies the payload into a per-ODT slot, and returns; the event trigger applies each slot through the same memory-write path `DOWNLOAD` uses. Buffering on arrival — rather than writing memory in the receive callback — is what keeps the CTO dispatch path unlocked despite `SWS_Xcp_00813` only guaranteeing non-reentrancy per PduId.

**Tech Stack:** C (AUTOSAR-style BSW), Jinja2 code generation via `bsw_code_gen`, pytest + CFFI compiling the real sources, all inside `xcp-test:local` under Docker.

**Spec:** `docs/superpowers/specs/2026-09-04-xcp-stim-sp3-design.md` — DD35 through DD45. Read it alongside this plan.

## Global Constraints

- **A DAQ-only build must be behaviourally identical.** It generates no STIM storage and no STIM code path. The unchanged suite is the proof.
- **Nothing is added to the CTO dispatch path** — no exclusive area, no guard on any handler reached from it. DD36 depends on this and §9 of the spec makes it an acceptance criterion.
- **Memory is never written in receive context.** Reception copies bytes into a slot; the trigger writes memory. DD36.
- **The payload length is written under `SchM_Enter_Xcp_StimBuffer` together with the payload.** A length paired with its data is the DD14 class. DD37.
- **A `DAQ_STIM` list applies before it samples**, so `StimBuffer` sections close before any `DtoQueue` section opens and the two areas cannot nest. DD40.
- **STIM absolute ODT numbers cap at `0xBF`**; the ceiling for a STIM-capable configuration is `0xC0`, not the `0xFC` of `XCP_DAQ_ABSOLUTE_ODT_COUNT_MAX`. DD42.
- **A timestamp is present on ODT 0 of a timestamped list**, sized by `Xcp_TimestampWireSize(Xcp_Ptr->general->timestampType)`, and is parsed and discarded. DD44.
- **An ODT entry with a non-zero `addressExtension` is skipped on apply and `Det`-reported** — `Xcp_WriteSlaveMemoryTable` has no parameter for it. DD45.
- Citations are to **XCP Part 2 Protocol Layer Specification 1.1** unless they name 1.0. New DAQ comments are qualified `1.1/...`.
- `raise(...)` is **not** a registered Jinja global; referencing it aborts rendering with `UndefinedError`. Guard tests assert generation *fails*, never that a message matches.
- **Measure the test baseline on the branch before changing anything.** Do not trust a number written in this plan.
- **`XCP_RESOURCE_PROTECTION_STATUS_MASK_STIM` stays ungated.** DD41: the protection check runs in
  `Xcp_CanIfRxIndication` from `Xcp_PIDToCmdGroupTable`, keyed on the PID *before* dispatch, where
  no list number is parsed and no direction is known — so the specification's rule ("DAQ list
  commands with DIRECTION = STIM") cannot be expressed without moving protection into the handlers,
  a change to every command. Do not wire this mask up because it looks unused; §8 of the spec
  records it as a follow-up.
- **Every new test is mutation-verified**: break the line it targets, confirm that test fails and others do not, restore, confirm `git diff` is clean.
